# Iris implementation spec

## Source decisions and audit

The hardware findings override the older PRD for board, display, pins and transport. Use AI-Thinker ESP32-CAM, OV3660, ST7735S 128×160 and Arduino ESP32 2.0.17. Replacement INMP441 capture and MAX98357A playback are now enabled; the Python host defaults to device audio. Physical operation still requires testing the assembled replacements.

The embedded baseline contradicts its prose: playback still blocks, microphone reads can lose samples, and drawing clears the screen. Replace these paths. Do not copy its positional JSON parser. The PRD's latency, cost and power numbers are targets, not measured results. At 40 MHz a 320×240 RGB565 transfer alone takes 30.72 ms, so its full-screen under-5-ms claim is rejected.

## Required behavior

- Firmware captures QVGA JPEG at a maximum target of 12.5 FPS (80 ms interval), reconnects to Wi-Fi/host, and renders a sprite at a target 30 FPS. Capture/network/audio run on core 0; LCD rendering runs on the Arduino loop on core 1, with the newest render snapshot passed through a one-entry queue. Unchanged rendered faces skip SPI transfers. Sleeping, idle/blinking, listening, thinking, talking and excited states are supported. Stale commands return to sleeping.
- Binary WebSocket messages contain one tag byte plus payload. Tags 1/2/3 mean JPEG/microphone/speaker. Audio is signed little-endian mono PCM16 at 16 kHz, up to 1024 samples per packet. Invalid or oversized packets are rejected.
- JSON controls use version 1, gaze_x/gaze_y in [-1,1], state and mouth_wave in [0,1]. Coordinates are display-relative; calibration can mirror horizontal tracking. The PRD's pupil coordinates are superseded.
- Host controls add optional `frame_ack`, a per-session count of processed/rejected frames. New firmware permits one outstanding frame until this count changes, with a five-second probe fallback; old hosts/firmware remain compatible without acknowledgement pacing. Gaze/state changes trigger immediate controls; unchanged controls keep the connection alive every 500 ms. QVGA JPEG quality is 24, uploads are bounded to 32 KiB and use one reusable packet buffer. PSRAM boards use two camera buffers with `CAMERA_GRAB_LATEST`; boards without PSRAM use one DRAM buffer. Eye smoothing is 0.65 on both sides, reducing deliberate tracking delay.
- Python host selects the largest face, smooths gaze, retains only the latest video frame, and runs vision and speech work outside the receive loop. No-face frames center the eyes. Per-device sessions isolate state and bound audio buffering.
- Vision initializes once outside the receive loop, limits OpenCV to two threads, and caps detection width to 320 pixels while preserving original image coordinates. Same-IP device reconnects retire a stale session instead of being rejected until TCP times out. Connection close reasons and last tracking duration are logged. WebSocket ping timeout is 30 seconds; device pong timeout is 15 seconds with three missed-pong attempts. The host receive queue allows eight packets of brief headroom; camera acknowledgement pacing still permits only one outstanding image.
- The HTTP preview encodes images on its worker threads, shares the encoding across viewers and omits unchanged JPEGs from repeat polls. The tracking loop retains only raw latest-frame bytes and metadata, without recording images.
- Voice uses energy endpoint detection, optional local Whisper, Ollama and Coqui adapters. Playback is paced PCM with mouth amplitude derived from audio. Half-duplex capture suppresses feedback during responses. Missing models produce explicit errors.
- Laptop input uses `sounddevice` RawInputStream callbacks and a bounded eight-chunk queue (32 ms chunks). The callback never runs model work. Native-rate input is resampled to 16 kHz mono PCM16 when needed. Overflow discards stale input and resets the utterance. Capture is session-scoped and closes on disconnect; audio captured during processing/playback or its 350 ms cooldown is ignored. Only the laptop source is accepted when it is active, avoiding duplicate ESP32 microphone input. `mic_device` selects an input index/name or the system default.
- Voice models initialize in the background and microphone/model failures preserve camera tracking. Voice inference limits CPU threads to avoid monopolizing the laptop. `--no-voice` overrides voice-enabled configuration for camera-only use.
- Audio selection defaults to `mic_source: "esp32"` and `speaker_output: "esp32"`; laptop input and output remain independently selectable fallbacks. Laptop output uses a session-scoped native-rate sounddevice stream with threaded driver calls and closes on disconnect. `speaker_local: true` allows host mouth animation with laptop output.
- Firmware uses I2S1 master TX/RX with shared GPIO4 BCLK and GPIO15 WS, GPIO1 microphone SD input and GPIO3 amplifier DIN output. Both source copies use these pins. Stereo 32-bit slots provide the microphone's required 64 clock pulses per 16 kHz frame. INMP441 L/R at GND selects the left slot. Signed microphone samples are DC-filtered before 2x gain (shift 15) and saturated to PCM16. Speaker PCM16 is expanded to 32-bit and duplicated into both slots, with partial writes preserved. Camera I2S0 is untouched.
- A separate core-0 microphone task drains DMA continuously into a sixteen-packet queue of 512 mono samples each (512 ms capacity). Capture is discarded before queuing while muted/offline, using an atomic gate shared with the network task. Queue overflow drops only its oldest packet. Sequence tracking emits `{"mic_gap":true}` before the first retained packet after loss, with a fresh continuity window on resume. Captures older than 500 ms are dropped. Network work prioritizes draining audio before camera capture; while microphone capture is enabled, the camera ceiling is 4 FPS (250 ms interval), otherwise 12.5 FPS. Host warnings are limited to gaps that interrupt an incomplete utterance; idle/response gaps are counted in session summaries. Host controls add `mic_enabled` only when the selected input is ESP32, models are ready, inference/playback is idle and cooldown has expired. Firmware discards pre-resume captures; disconnect and stale controls disable uploads. No runtime Serial; remove UART programming connections on GPIO1/3 for normal audio operation. `IRIS_AUDIO_ENABLED=0` releases audio pins for camera/display-only operation.
- The selected installed Ollama model is `qwen3.5:4b`, with thinking disabled and a ten-minute keep-alive. Host model loading is shared and awaited for ESP32 input as well as laptop input.
- A host-side microphone meter measures accepted source PCM before utterance gating, holds scalar RMS/peak metrics for 500 ms, reports packet age/count, clipping and gaps, and retains no raw audio. HTTP metadata updates independently of camera frames. The preview shows a logarithmic level pointer and the actual endpoint threshold. Terminal logs show two-second window maxima. `--mic-test` streams microphone samples for diagnostics without loading voice models or creating replies; normal half-duplex gating remains unchanged in voice mode.
- A local simulator exercises controls without hardware. Configuration and diagnostics are documented. No raw camera/audio recording by default.

## Display, speech and connection recovery

The LCD waits 500 ms for its supply before initialization. With RESET tied to 3.3V and no MISO, firmware cannot detect a panel-only white screen. The drawing core therefore repeats the panel's software initialization every 30 seconds, deferring during talking, and repaints unchanged content at least every two seconds. Recovery may briefly blank the panel (approximately one second with the installed ST7735 initialization sequence); network and external audio continue on core 0. `DISPLAY_REINIT_MS` controls this fallback interval. This cannot repair a disconnected display, unstable supply or a controller that ignores SPI commands.

Speech synthesis receives words with emoji, variation selectors, skin modifiers, keycaps and joining characters removed; emoji-only replies use a short spoken fallback. The system prompt also requests plain spoken text. Invalid/nonfinite synthesized audio is rejected. Recognition/reply/synthesis have a combined 90-second host deadline; a timed-out response resets thinking, mouth and microphone gating to idle. Socket writes have five-second deadlines. Host timeouts use Python 3.11's `asyncio.timeout` so cancellation cannot be swallowed when an event or send finishes during disconnect; a regression test reproduces the previously stuck shutdown. Cancellation cannot kill an inference thread; the existing global brain lock prevents overlapping inference if that thread is still finishing.

Firmware disables automatic Wi-Fi reconnect and retries `esp_wifi_connect()` every 15 seconds while disconnected, avoiding forced disconnects that interrupt an in-progress association. Device health is sent every ten seconds only when host controls advertise `device_health: true`, preserving compatibility with old hosts. Notices contain uptime, Wi-Fi drop count/reason, host drop count, RSSI, free heap and boot/reset cause. The host validates and logs the first report and changed drop counters. These distinguish radio loss, socket loss and reboot; sustained operation on the physical network remains unverified.

## Acceptance and scope

Host speech threshold is adjustable through `mic_threshold` or `--mic-threshold`, validated as a finite fraction strictly between 0 and 1. The generic default is 0.015; the current device configuration uses 0.04 for filtered 2x-gain microphone PCM. Firmware conditions signed 24-bit samples with a stateful 60 Hz high-pass before gain and PCM16 saturation, resetting while muted; this removes offset/drift but cannot recover already-corrupted or missing input. Preview and terminal expose diagnostic AC RMS and absolute DC offset of the received PCM. Empty recognition is logged and makes no AI request; recognized text, replies and synthesized duration are logged. Empty response audio skips playback. Physical noise/bias investigation is still required if normal speech cannot cross the configured threshold. Enabled microphone capture throttles the camera even while the endpoint is idle; the sixteen-packet/500 ms freshness bounds provide more headroom for brief stalls, with possible additional latency.

Automated checks cover framing, validation, gaze mapping, utterance limits and a real WebSocket session. Firmware build and physical camera/display/audio tests are separate acceptance gates. Timing and electrical claims require physical measurement.

This pass implements the companion core, firmware, local voice adapters and simulator. Research studies, emotion recognition, multi-user identity tracking and a configuration web UI remain roadmap work.
